# Portfolio Design Direction

## 1. Existing identity is the baseline

The current portfolio has a deliberate editorial/creative feel.

Preserve the recognizable visual language unless a specific element creates a real problem with:

- comprehension;
- accessibility;
- responsiveness;
- credibility;
- performance;
- interaction;
- consistency.

The goal is not “make it look more modern.”

The goal is:

> make the existing design feel more finished.

## 2. Audience

The portfolio serves several plausible audiences:

- software recruiters;
- engineering hiring managers;
- founders;
- clients;
- game-development collaborators;
- creative/media collaborators;
- design/creative leads.

The site should be broad enough to represent a multidisciplinary career without becoming vague.

## 3. Positioning hierarchy

A first-time visitor should understand in seconds:

**Name → role(s) → what Moses builds → evidence → contact path.**

Do not make visitors infer the professional positioning entirely from project thumbnails.

The current positioning around full-stack development, game development, creative direction, products, games, design, and motion should stay coherent.

## 4. Visual hierarchy

Use visual weight intentionally:

1. identity and positioning;
2. strongest/most relevant work;
3. project contribution and evidence;
4. capabilities;
5. biography/context;
6. contact.

Do not let decorative metadata overpower project titles and outcomes.

## 5. Typography

Preserve the existing type direction if technically sound.

Audit:

- line length;
- line-height;
- heading balance;
- overly tight mobile typography;
- extremely large display text;
- low-contrast secondary text;
- inconsistent type styles between sections.

Portfolio text should feel authored, not generated by a component library.

## 6. Spacing

Retain the generous composition while removing accidental dead space.

Use spacing to clarify:

- section boundaries;
- project hierarchy;
- metadata grouping;
- content relationships.

On mobile, reduce desktop-scale section gaps proportionally.

## 7. Project cards

Project cards are evidence, not just decoration.

A good card lets a visitor scan:

- project name;
- type;
- status/year;
- short value description;
- relevant stack/skills;
- clear path to detail;
- live/demo/source links when actually available.

Do not overload cards with every detail that belongs in the case study.

## 8. Imagery

Project imagery should do real explanatory work.

Prefer:

- real screenshots;
- product UI;
- gameplay views;
- branded assets;
- motion/video stills;
- real project outputs.

Avoid adding generic stock imagery.

Preserve image aspect ratios intentionally and prevent layout shift.

## 9. Motion

Motion may express creative direction, but content must remain immediately usable.

Keep motion:

- fast;
- subtle;
- purposeful;
- interruptible;
- reduced under `prefers-reduced-motion`.

Avoid:

- long reveal delays;
- scroll hijacking;
- cursor-following spectacle;
- mandatory intro screens;
- motion that hides project content before intersection observers fire;
- animation on every single text node.

## 10. Color

Preserve the existing palette.

Improve only:

- contrast;
- state clarity;
- focus visibility;
- consistency;
- semantic use.

Do not introduce trendy neon/AI gradients just to signal “tech.”

## 11. Personal feel

The portfolio should feel handmade and specific to Moses.

Avoid generic language and generic UI patterns that could belong to any developer.

The strongest personal signals are:

- the actual project mix;
- concise project stories;
- clear personal contribution;
- deliberate visual treatment;
- thoughtful writing;
- consistent craft.

## 12. Contact

The contact experience should be easy to find and low-friction.

Preserve verified contact channels.

Do not expose additional personal data or invent new channels.

If direct contact information is publicly visible, preserve it unless explicitly instructed otherwise, but report privacy/spam trade-offs instead of silently changing it.

## 13. Responsive principle

Mobile should feel composed, not collapsed.

Preserve:

- reading order;
- identity;
- project prominence;
- easy contact;
- usable filters.

Avoid simply shrinking desktop typography and spacing.

## 14. SEO/social principle

The portfolio should present a clean professional identity when:

- searched by name;
- shared on LinkedIn/WhatsApp/Discord;
- opened as a project link;
- crawled by search engines.

Each indexable case study should identify both the project and Moses's contribution where appropriate.

## 15. Final standard

A successful refinement should make the current design feel:

- more intentional;
- more credible;
- easier to scan;
- easier to navigate;
- stronger on mobile;
- more accessible;
- faster;
- better at proving actual skill.

It should **not** look like a new template was installed.

# Content, Credibility, and Privacy Standards

## 1. Accuracy

Portfolio credibility depends on accurate self-representation.

Never invent:

- responsibilities;
- employment;
- client relationship;
- outcomes;
- users;
- metrics;
- team size;
- technologies;
- launch state;
- project ownership.

## 2. Project status

Use consistent meanings for terms such as:

- Live;
- In development;
- Ongoing;
- Internship;
- Project.

Audit whether each label describes:

- availability of a live link;
- project lifecycle;
- work context;
- year.

Do not silently reinterpret labels.

## 3. Counts

If the hero displays counts such as selected works/live launches/disciplines:

- verify them against the project data;
- derive automatically when practical;
- avoid stale manually maintained numbers.

## 4. Role clarity

For each project, distinguish:

- product/project description;
- personal contribution.

A beautiful portfolio becomes less credible if a reviewer cannot tell what the portfolio owner actually did.

## 5. Internship/team work

State internship context honestly.

Do not present organizational/team projects as solo commercial work unless that is accurate.

## 6. Live/source links

Only label something `Live`, `Demo`, or `Source` if the destination supports that label.

Check for:

- broken links;
- private repositories;
- dead deployments;
- auth walls;
- placeholder domains.

## 7. Contact privacy

The current public site includes direct communication channels.

Do not add more personal details.

If direct phone/contact data is already public:

- preserve it unless explicitly asked to remove it;
- flag privacy/spam exposure for human review;
- do not duplicate it across additional metadata or structured data automatically.

## 8. Social handles

Verify displayed label and actual href.

If two channels use similar but different handles, do not assume one is wrong.

Report mismatches or suspicious inconsistencies for manual confirmation.

## 9. Availability messaging

`Available for select projects` is time-sensitive.

Keep such text easy to update.

Do not put it into structured data or multiple duplicated components unless there is a single source of truth.

## 10. Personal branding

If both `Runodev` and `Moses Onerhime` are intentional identities:

- preserve both;
- make the relationship understandable enough that visitors are not confused.

Do not rename the site or remove Runodev without instruction.

## 11. Testimonials

Do not add testimonials unless real approved quotes and attribution exist.

## 12. Metrics

Do not convert ordinary project facts into fake metrics.

Examples to avoid:

- “40% faster”;
- “10K users”;
- “99% uptime”;
- “3x engagement”.

Use qualitative outcomes when no measured metric exists.

## 13. AI-generated tone

Avoid portfolio copy that reads like generic AI marketing:

- “cutting-edge”;
- “seamless experiences”;
- “transforming ideas into reality”;
- “leveraging innovative technologies”;

unless the phrase is intentional approved brand copy.

Prefer concrete descriptions of what was built.

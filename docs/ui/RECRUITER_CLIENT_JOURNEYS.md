# Recruiter, Client, and Collaborator Journeys

The portfolio has multiple audiences. Design for all without creating separate websites.

## Journey A — Recruiter / hiring manager

### Goal
Determine professional relevance quickly.

### Preferred path
Home → selected projects → case study → capabilities/about → contact/CV

### Optimize for
- immediate role clarity;
- scannable projects;
- contribution clarity;
- real stack;
- implementation evidence;
- clear contact.

### Avoid
- forcing full-page animation;
- obscure navigation;
- project cards with visuals but no role/context;
- enormous skill clouds;
- walls of biography.

## Journey B — Founder / client

### Goal
Decide whether Moses can build or help shape a product/website.

### Preferred path
Home → relevant project → case study/live example → capabilities → contact

### Optimize for
- real deliverables;
- clarity on capabilities;
- professional presentation;
- live examples;
- low-friction contact.

### Avoid
- jargon without outcomes;
- unclear distinction between project and personal contribution;
- hidden communication path.

## Journey C — Game collaborator

### Goal
Evaluate Beyond 90/game-development ability and creative direction.

### Preferred path
Home → Beyond 90 → related game/creative capability → contact

### Optimize for
- gameplay/product evidence;
- current development status;
- role;
- footage/images;
- system depth.

## Journey D — Creative/media collaborator

### Goal
Evaluate editing, motion, branding, and creative direction.

### Preferred path
Home → Furreal.aex / creative project → creative direction capability → social/live work → contact

### Optimize for
- high-quality media;
- fast playback/preview;
- clear role;
- visual taste;
- direct path to published work.

## Journey E — Search/social visitor

### Goal
Arrive directly on a project or homepage from search/social.

### Optimize for
- descriptive metadata;
- strong Open Graph image;
- project context without requiring homepage first;
- clear identity link;
- reliable canonical URLs;
- mobile experience.

## Global journey rules

Every major page should offer a next step.

Do not require a specific linear journey.

A visitor should be able to enter on a project page and still answer:

- whose portfolio is this?
- what project is this?
- what was the role?
- what should I explore next?
- how do I make contact?

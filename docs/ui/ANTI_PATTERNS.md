# Portfolio UI Anti-Patterns

## No unnecessary redesign

Do not:

- swap the entire palette;
- replace typography casually;
- replace current layouts simply because a different one is trendy;
- convert the portfolio into a standard centered developer template.

## No generic developer-portfolio clichés

Avoid adding:

- code rain;
- fake terminal windows;
- rotating technology-logo clouds;
- skill percentage bars;
- fake GitHub contribution graphs;
- typing animations for basic identity copy;
- “Hello World” decoration;
- giant technology logo walls;
- floating 3D laptops;
- fake command-line navigation.

Unless the current brand specifically uses one of these, do not introduce it.

## No generic AI aesthetic

Avoid:

- purple/blue glow everywhere;
- glassmorphism everywhere;
- animated grid backgrounds;
- gradient blobs;
- particle fields;
- excessive pill badges;
- aurora backgrounds.

## No motion showcase at the expense of work

Do not:

- hide the work until scrolling;
- force page-load intro animations;
- animate every line;
- hijack scroll;
- use long page-transition sequences;
- add custom cursors that reduce usability.

## No project-card clutter

Do not put:

- all technologies;
- all responsibilities;
- all outcomes;
- all links;

into the card.

Cards are summaries; case studies hold detail.

## No fake metrics

Do not invent impact numbers.

## No fake testimonials

Do not invent clients or quotes.

## No content removal for “minimalism”

Do not remove useful:

- project context;
- role;
- status;
- contact;
- accessibility labels;
- navigation;
- case-study evidence.

## No inaccessible minimalism

Do not use:

- ultra-low contrast grey;
- tiny metadata;
- hover-only descriptions;
- unlabeled icon buttons;
- hidden focus;
- tiny mobile controls.

## No card-inside-card systems

The site should remain editorial and project-led.

Avoid nested rounded panels unless they solve a clear grouping problem.

## No dependency bloat

Do not add:

- an entire component library;
- a second animation framework;
- WebGL;
- three.js;

for minor visual polish.

## No route breakage

Do not rename project URLs for aesthetics.

## No “industry standard” homogenization

Industry standard means:

- accessible;
- fast;
- clear;
- credible;
- responsive;
- maintainable.

It does **not** mean making the site look like everyone else's portfolio.

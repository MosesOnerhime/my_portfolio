# Portfolio Positioning Standards

## 1. Portfolio job

The portfolio is a decision tool.

A useful visitor decision is:

> “Is this person relevant to what I need, and is there enough evidence to contact them?”

Aesthetic quality supports that decision; it should not replace it.

## 2. Multi-disciplinary positioning

The current portfolio combines:

- full-stack development;
- product development;
- game development;
- UI/experience design;
- creative direction;
- motion/video work.

This breadth is a strength if the hierarchy is clear.

Avoid making the hero sound like a list of unrelated skills.

Use the projects to prove the breadth.

## 3. First-screen test

Without scrolling far, the visitor should know:

- the name;
- primary professional identity;
- the kind of things built;
- a path to work;
- a path to contact.

Do not bury the work behind an overly cinematic introduction.

## 4. Recruiter scan path

A recruiter may scan:

1. identity/role;
2. 2–4 strongest projects;
3. technologies/skills;
4. case-study contribution;
5. work history/context;
6. contact.

Make those paths easy without requiring every visitor to read the entire homepage.

## 5. Client scan path

A client/founder may scan:

1. capabilities;
2. project quality;
3. whether similar work exists;
4. professionalism;
5. live examples;
6. contact.

The site should let them understand possible engagement without vague sales copy.

## 6. Creative collaborator scan path

A creative/game/media collaborator may care more about:

- visual taste;
- original IP;
- motion;
- creative direction;
- gameplay/product craft.

Preserve enough visual personality for this audience while keeping navigation conventional.

## 7. Selected work vs complete archive

Research on hiring portfolios consistently favors curation and scannability.

Because this portfolio intentionally demonstrates several disciplines:

- do not delete valid projects;
- keep a curated “selected” presentation;
- make the strongest projects visually prominent;
- keep additional work available;
- avoid giving every project identical visual priority if some are substantially stronger.

## 8. Evidence over skill lists

Skills are more convincing when attached to projects.

Prefer:

> React + TypeScript — Drixil Group / CalVision

over a giant undifferentiated logo cloud.

The existing capability and project-tag approach is preferable to a generic skill-meter section.

## 9. Availability

If the site displays availability:

- treat it as time-sensitive content;
- keep it easy to update;
- do not infer availability from old content;
- do not duplicate it in many places unless sourced centrally.

## 10. Resume/CV

If a verified resume/CV file already exists in the repository, make it easy to find without turning it into the dominant CTA.

If it does not exist, do not generate or link a fake placeholder.

## 11. Contact hierarchy

Use one primary contact action.

Secondary channels can remain available for different audiences.

Avoid displaying many equally prominent communication options before the visitor understands which one is preferred.
